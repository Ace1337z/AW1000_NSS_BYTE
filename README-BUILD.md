## Target
- board: `qualcommax/ipq807x`, profile `arcadyan_aw1000` (IPQ8072A, 1 GB RAM)
- only that device is selected; the other 32 devices of the `ipq807x-1g` group
  are forced `=n` in `builder/local/aw1000.fragment`
- image: squashfs sysupgrade only (no factory, no initramfs)
- offload: PPE via fw4 flowtable + `nss-wifi-drv` (ath11k data path on NSS cores).
  Pinned on both at build time (`aw1000.fragment`) and at runtime
  (`etc/init.d/aw1000-nss`, START=18): offload=1, `flow_offloading`/`_hw`=1 and
  the flow-table include are re-asserted before `nss-wifi` (START=19) probes
  the radios. `/etc/nss-wifi.pending` is left alone, so a bring-up the board did
  not survive is still skipped once.
- kernel: `linux-6.18.60` (from the `ppe-nss` feed). That is newer than what
  upstream QModem CI tests, so the out-of-tree modem modules are smoke-built
  before the world build (see Build).
- the modem data path is **not** NSS-offloaded: `kmod-rmnet-nss`,
  `kmod-qmi_wwan_q_nss` and `kmod-pcie_mhi_nss` all need `kmod-qca-nss-drv`
  (`@NSS_DRV_RMNET_ENABLE`), which ppe-nss does not ship — that vendor host
  driver is exactly what the PPE path replaces. Wi-Fi NSS offload and the fw4
  flowtable still apply; only wired/modem traffic stays on the CPU.
  `quectel_MHI` (vendor MHI, `CONFIG_PACKAGE_kmod-pcie_mhi=y`) is patched so its
  `rmnet_nss_callbacks` reference is compiled out when `kmod-rmnet-nss=n`;
  without that patch `modpost` aborts the build with
  `ERROR: modpost: "rmnet_nss_callbacks" [pcie_mhi.ko] undefined!`.

## Device defaults baked into the image
All of these live in `builder/devices/ipq807x-1g/files.ppe-nss/`, so a fresh
build reproduces them.

### Login: `root`, no password
- base-files already ships `root::` in `/etc/shadow`.
- `etc/uci-defaults/97-aw1000-root-blank` re-empties the hash once and records
  `system.@system[0].aw1000_root_blank=1` so a later password survives a
  settings-keeping sysupgrade. Clear that option to re-apply.
- This image ships **openssh-server** (`builder/devices/common/config` sets it,
  dropbear stays `=m`). `etc/ssh/sshd_config.d/10-root-login.conf` sets
  `PermitRootLogin yes` and `PermitEmptyPasswords yes`; the stock sshd_config
  leaves password auth on, so blank-password SSH works. Set a password before
  exposing SSH anywhere untrusted; LuCI accepts the blank password too.

### Wi-Fi: `BYTE` on 2.4 + 5 GHz, open, country `US`
- `etc/board.d/99-aw1000-wifi` runs during preinit (`/bin/board_detect`) and
  writes `wlan.defaults` into `board.json`:
  `ucidef_set_country US`, `ucidef_set_wireless 2g "BYTE" none`,
  `ucidef_set_wireless 5g "BYTE" none`.
- `/lib/wifi/mac80211.uc` generates `/etc/config/wireless` from that on first
  ieee80211 hotplug. A country is mandatory: without one it generates 5 GHz APs
  disabled. Existing radios are skipped, so a user-changed SSID/key is never
  overwritten.
- No key on purpose. LAN stays `192.168.1.1/24` with DHCP.

### Dashboard widgets (modem / thermal / storage)
- `aw1000-dashboard` vendors three widgets (mobile, thermal, storage), `cell.js`
  / `mcc.js`, the ACL and the `aw1000-leds` poller from
  XT-Martinez/aw1000-feed `aw1000-defaults` @ a7e14ad. The rest of
  `aw1000-defaults` is **not** imported: its quectel-proto `wwan` interface,
  open 2.4 GHz-only board.d, fstab anon-mount, LED ownership changes and theme
  override would fight QModem and this tree's own defaults.
- `aw1000-leds` polls the modem's second AT port (`/dev/ttyUSB3` by default,
  `/etc/config/aw1000_leds`) under a shared modem lock, writes
  `/tmp/aw1000-status/{live,static,history,thermal}` and drives the front panel
  LEDs. Widgets hide themselves until those files exist.
- Local change: the poller calls `sms_tool_q` instead of `sms_tool`, so the
  image does not carry a second AT/sms binary next to QModem's.
- The NSS-offload card is replaced by a **Storage** card reading
  `system.info` (`/overlay` used/total/free). The old card could never show
  anything: this image has `nss-firmware` but no `kmod-qca-nss-ecm`, so its
  counter file stayed empty.
- `luci-mod-dashboard` is patched
  (`builder/patches/feeds/ppe-nss/luci/0001-dashboard-hide-tabs-and-layout.patch`):
  the bottom detail tabs and the Layout editor are hidden; only the cards and
  live charts remain.
- Disable the poller with `uci set aw1000_leds.main.enabled=0` if the extra AT
  client is unwanted; widgets then stay hidden.

### Hostname and login banner
- `etc/uci-defaults/96-aw1000-hostname` sets `system.hostname=BYTE` and
  `system.description=BYTE by ACE` once (marker `aw1000_hostname`). A DNS label
  cannot contain spaces, so the byline lives in the description and banner.
- `etc/banner` replaces the stock OpenWrt ASCII logo with a BYTE logo and the
  byline. It shows on serial and on every SSH login.

### RJ11 phone (Si32261) and SIP
- `etc/fxs/si3226x_patch.bin` is in the image (908 bytes, serial `0x05262017`,
  `python3 tools/mkpatch.py --check` clean): the Skyworks ProSLIC DSP patch that
  `fxsd` loads on every start. Without it `fxsd` refuses to start, so it is no
  longer a manual copy step. It is third-party vendor code; this tree only
  redistributes the binary the stock firmware uses.
- PCM mode is checked, not assumed: `fxsd` issues `AT+QDAI?`, and if the modem
  reports master it sends `AT+QDAI=x,1,0,4,0,<rate>,1,1` and restarts the modem,
  then keeps watching. `fxs` does not need a `pcm`/`slave` option.
- `etc/uci-defaults/92-aw1000-phone` (marker `fxs.main.aw1000_phone`) turns the
  port on, sets `fxs.main.patch`, `callerid bellcore`, `callerid_timing after`,
  `ringback 1`, keeps call history (`history_autodelete 0`, 30 days) and sets
  `fxs.main.sip=1`.
- SIP is pre-configured on the LAN side: `qmodem_sip.inbound` gets
  `enabled=1`, `interface=lan`, `listen_port=5060`, `transport=udp_tcp`,
  username `byte` and a random 24-character password (`A-Za-z0-9_-`, the
  charset qmodem-sipd accepts). Credentials are written once to
  `/root/SIP-CREDENTIALS.txt` (mode 0600). Outbound SIP stays disabled: it needs
  a provider's server and account.
- Dial tone, ringing, DTMF, caller ID, hold, speed dial, blocked numbers and
  call history are `fxsd`/`luci-app-fxs` features; the pages are under
  **Services → Phone (RJ11)**. Speed dial and blocked numbers are empty lists by
  design (no invented numbers).
- Not selected: `luci-app-qmodem-next`/`-monitor`, `luci-app-qmodem-hc`,
  `luci-app-qmodem-ttl`, `sms-forwarder` (unchanged from before). QModem voice
  and SIPd **are** selected: `qmodem-voip`, `qmodem-sipd`,
  `luci-app-qmodem-voip`.

### Modem uplink: MTU 1420 and interface recovery
- Every (re)dial sets `network.<if>.mtu=1420` and `network.<if>v6.mtu=1420`
  (`builder/patches/feeds/ppe-nss/qmodem/0003-modem-mtu-1420.patch`), and
  `qmodem-ipv4-event` forces `mtu=1420` instead of taking the modem's DHCP
  value, so a reconnect cannot land 1500 again. The v6 interface shares the
  netdev, so it follows.
- `etc/hotplug.d/iface/97-aw1000-modem-mtu` re-pins the netdev after every
  `ifup`/`ifupdate` of an interface that carries `modem_config`, covering the
  `proto dhcp` path where udhcpc would otherwise apply the offer's MTU.
- `hang()` deletes `network.<if>`/`network.<if>v6` through `flush_if`, and the
  auto-dial monitor never calls `set_if` again, so the uplink could stay gone
  until the modem was re-added.
  `builder/patches/feeds/ppe-nss/qmodem/0004-recreate-modem-if-after-hang.patch`
  adds `ensure_modem_if()`: it checks the sections the current PDP type needs
  and calls `set_if` once when one is missing. It is a no-op when everything
  exists and is called from both `qmi_dial` and `at_dial`.

### IPv6: detected at start, IPv4 preferred when absent
- `etc/uci-defaults/98-aw1000-ipv6` creates `wan6` (`proto dhcpv6`,
  `reqaddress try`, `reqprefix auto`, `peerdns 1`) on the WAN device and sets
  `network.lan.ip6assign=60` so a delegated prefix is usable. Without a
  delegation nothing is assigned and IPv4 is unaffected. The modem side is
  QModem's own `<if>v6` interface (`proto dhcpv6`), created when the PDP type is
  `ipv4v6`; nothing extra is needed for it.
- Nothing is disabled. `/usr/sbin/aw1000-ipv6-prefer` checks for a v6 default
  route **and** a non-ULA global address (`fc00::/7` and tentative/DAD-failed
  addresses do not count). If either is missing it sets dnsmasq
  `filter_aaaa=1` so LAN clients get IPv4 answers instead of stalling on AAAA;
  it clears the filter as soon as v6 works.
- Called from `etc/init.d/aw1000-ipv6` (S95, detached after a 15 s settle) and
  from `etc/hotplug.d/iface/95-aw1000-ipv6-fallback` (detached after 5 s, one
  run at a time via `/tmp/aw1000-ipv6.lock`, so `hotplug-call` is not blocked).
- Opt out with `touch /etc/aw1000/keep-aaaa` (e.g. LAN with only local ULA
  hosts). State is re-detected at every boot.

## Tuning
### sysctls — `etc/sysctl.d/99-aw1000-tuning.conf`
Applied by `/etc/init.d/sysctl` (START=11) every boot:
```
net.core.default_qdisc=fq
net.ipv4.tcp_congestion_control=bbr
net.ipv4.tcp_fastopen=3
net.ipv4.tcp_slow_start_after_idle=0
net.core.netdev_max_backlog=16384
net.core.netdev_budget=2400
```
`kmod-tcp-bbr` only ships `12-tcp-bbr.conf` with the congestion control line;
this file is the complete set. `kmod-sched` provides `sch_fq.ko`. PPE-offloaded
flows bypass the qdisc and stack sysctls after the first packet, so these matter
on the first packet and on non-offloaded/low-rate paths.

Optional fq tuning (not automated; fq's `flow_limit`/`quantum`/
`initial_quantum` are tc options, not sysctls). Example for the modem link:
```sh
tc qdisc replace dev wwan0_1 root fq quantum 1514 initial_quantum 15140 flow_limit 1024
```
Persist it from a hotplug script if wanted; the default `fq` qdisc from
`net.core.default_qdisc` already applies to new interfaces.

### CPU governor + modem IRQ spread — `etc/init.d/aw1000-tuning` (S99)
- sets `performance` on every `cpufreq` policy (the kernel boots on schedutil;
  `CONFIG_CPU_FREQ_GOV_PERFORMANCE=y` is present but not the default);
- after boot, retries for up to 60 s to place `mhi`, `mhi_net`, `xhci*`, `dwc3`
  and `pcie*` IRQs round-robin over the secondary CPUs (`smp_affinity_list`),
  leaving CPU0 for housekeeping/NAPI. IRQs that refuse the write are skipped;
  IRQ numbers are matched by name, not number.

### zram — `etc/uci-defaults/94-aw1000-zram`
512 MB, zstd (`kmod-zram` + `zram-swap` + `CONFIG_KERNEL_ZRAM_BACKEND_ZSTD=y`).
`zram-swap` starts at START=15, after uci-defaults have run. If the kernel does
not advertise zstd, zram-swap keeps its built-in default (lzo-rle).

### vnstat — database moved to `/etc/vnstat`
- `etc/uci-defaults/95-aw1000-vnstat-dbdir` creates `/etc/vnstat`, rewrites
  `DatabaseDir "/etc/vnstat"` in `/etc/vnstat.conf` and sets
  `system.@system[0].aw1000_vnstat_dbdir=1`. `/var` is tmpfs, so the counters
  would otherwise reset every boot; `/etc` is on the overlay and survives
  sysupgrade.
- `luci-app-vnstat2` is installed but its "Traffic Monitor" menu node is hidden
  by `usr/share/luci/menu.d/zz-aw1000-hide-vnstat2.json` (later glob order
  replaces `depends` with a test for `/etc/aw1000/show-vnstat2`, so the parent
  node and its children disappear). Unhide:
  `mkdir -p /etc/aw1000 && touch /etc/aw1000/show-vnstat2`.
  The menu still exists in the image; nothing is removed at build time.

## Build
```sh
cd /home/ace/AW1000_NSS_BYTE
./prepare.sh          # feeds + .config + overlay staging (idempotent)
./ci/preflight.sh     # seconds: symbols, patches, staging, script/JSON syntax
./build.sh            # the only step that compiles; JOBS=2 default
```
`ci/preflight.sh` is the cheap gate: it checks that every fragment symbol
survived into `.config`, that each builder patch is applied cleanly to the
pinned feed, that every overlay file (and the decoded vendor blob, md5
`3778fa32…`) reached `openwrt/files` with the right mode, and that no
transport file (`*.b64`, `*.orig`, `*.rej`) leaked into the staged rootfs. It
exits non-zero on any failure and runs in CI before the compile, so a broken
definition fails in seconds instead of hours. It never compiles anything —
`./build.sh` (or the workflow) is the only step that does.

Build verbosity is not cosmetic. With no `V=` on the make command line,
`include/verbose.mk` runs every sub-make as `>/dev/null 2>&1`, so a failing
package reports only `ERROR: package/X failed to build` and the compiler
diagnostic is discarded - which is exactly how a 4 h CI run failed without
telling us why. `build.sh` therefore runs `make V=s` (keeps the compiler
output) and, when the build fails, re-runs each named builddir with
`make V=sc <builddir>/{clean,compile}` so the real error lands in the same run.
`SMOKE=1` (default) compiles tools, toolchain, kernel and the four
out-of-tree kernel modules (`quectel_MHI`, `quectel_QMI_WWAN`,
`simcom_QMI_WWAN` — none of which upstream CI builds — and `aw1000-fxs`, the
SLIC driver) before the long `world` build: no extra cost when it passes
(stamps are reused), an hour instead of four when a kernel module breaks.
`SMOKE=0` skips it. CI uploads `build.log` as an artifact on failure.

The builder's default `CONFIG_ALL_KMODS=y` is turned off (`aw1000.fragment`):
with it, `world` compiles every kernel-module package in every feed (~1100
modules), and any legacy driver that does not track the current kernel API
fails the build even though it is not in the image. PF_RING 9.2.0
(`kmod-pf-ring`) is the known casualty on `linux-6.18.60` (sockaddr
prototype change + `-march=native`). The image ships exactly the selected
`=y` modules; `ci/preflight.sh` fails if `CONFIG_ALL_KMODS` or
`kmod-pf-ring`/`libpfring` come back.

Machine: 4 threads, 5.8 GB RAM + 4 GB swap → `-j2`. LTO + mold + GCC 15 make
`-j4` swap-thrash. `make defconfig` prints harmless recursive-dependency errors
(qt5base-gui, fwknopd, squeezelite-custom).

Output:
`openwrt/bin/targets/qualcommax/ipq807x/*arcadyan_aw1000*squashfs-sysupgrade.bin`

## Releases
Releases are named after the build: **`BYTE <version>`**, version `1.0.x`,
starting at `1.0.1` (`./VERSION`). `build.sh` calls
`builder/local/stage-release.sh`, which:

- copies the sysupgrade image to `releases/BYTE-<version>/` as
  `BYTE-<version>-arcadyan_aw1000-squashfs-sysupgrade.bin`;
- writes `sha256sums`;
- writes `RELEASE.md` with the sources' commits, kernel/NSS firmware, package
  versions and the feature list of *that* build.

Upload with `builder/local/stage-release.sh --publish` (`gh release create
BYTE-<version>` with title `BYTE <version>` and `RELEASE.md` as notes). Bump
`./VERSION` to `1.0.2`, `1.0.3`, ... for the next build. Never reuse a version.

## Installing
There is **no factory image**. The device must already run OpenWrt, or be
recovered to it over serial/TFTP first. Before flashing, make sure a serial
console or the vendor TFTP recovery path is reachable, and keep a known-good
image plus a config backup.

1. Back up config.
2. First flash with settings **off** (`sysupgrade -n image.bin`); later flashes
   may keep settings.
3. After boot: LAN `192.168.1.1`, LuCI login `root` with no password, Wi-Fi
   SSID `BYTE` open on 2.4 + 5 GHz (country US), no SSH password either until
   one is set.

- `swapon --show` / `zramctl` → 512 MB zram, zstd
- `grep DatabaseDir /etc/vnstat.conf` → `/etc/vnstat`; `ls /etc/vnstat` shows
  `vnstat.db` after the first sample
- LuCI dashboard shows mobile/thermal cards plus a Storage card; no bottom tabs
  and no Layout editor (patched out). NSS card is gone by design.
- `hostname` → `BYTE`, `uci get system.@system[0].description` → `BYTE by ACE`,
  `/etc/banner` shows the BYTE logo
- NSS enforcement: `uci get nss-wifi.general.offload` → `1`,
  `uci get firewall.@defaults[0].flow_offloading_hw` → `1`, service
  `/etc/init.d/aw1000-nss enabled` → yes; `logread | grep aw1000-nss` after
  changing one by hand, then reboot
- BYTE panel: LuCI → **Services** → BYTE, page loads AdGuard Home status
- modem: `uci show qmodem`, QModem page reports the card; TTL chain contains
  `oifname "wwan0_1" ip ttl != 64 ip ttl set 64` (`nft list chain inet fw4

- MTU: `ip -4 link show wwan0_1 | grep mtu` → `mtu 1420` after a redial, and
  `uci get network.wwan0_1.mtu` → `1420` (name follows the QModem alias)
- hang recovery: `ubus call network.interface.wwan0_1 down` does not delete the
  section; after a real modem hang (`/usr/share/qmodem/modem_dial.sh <cfg> hang`)
  the next dial recreates `network.<cfg>`/`network.<cfg>v6` — check
  `logread | grep 'missing after hang'`
- phone: `/etc/init.d/fxsd status` running, `logread -t fxsd` shows the patch
  loaded and `modem audio`/slave message, `uci get fxs.main.sip` → `1`;
  `cat /root/SIP-CREDENTIALS.txt` holds the LAN SIP login
- IPv6: `ip -6 route show default` and `ip -6 addr show scope global`; when
  empty, `uci get dhcp.@dnsmasq[0].filter_aaaa` → `1`, and it returns to `0`
  once a v6 route appears
- recovery: boot into failsafe (`failsafe` on serial) and re-flash the previous
  image

## Known risks / open items
- `kmod-aw1000-fxs` is an out-of-tree Si32261 SLIC driver and the least proven
  piece here. Drop `CONFIG_PACKAGE_luci-app-fxs=y` if it fails to load.
- LAN SIP is on by default with a generated password; the account is reachable
  from `lan` only. Change `qmodem_sip.inbound.password` (or set
  `fxs.main.sip=0`) if SIP is not wanted.
- MTU 1420 is fixed on the modem uplink; it costs ~5 % of the payload on
  non-VPN traffic but keeps VPN/tunnel overlays under the carrier MTU. Change
  the two `1420` values (QModem patch + hotplug) if a line needs 1500.
- The TTL rewrite is bypassed for PPE-offloaded flows; offload is intentionally
  left enabled. Test with a real tethered client.
- `aw1000-leds` is a second AT client. It takes the shared modem lock and skips
  a poll when busy, but a persistent AT conflict is possible; disable it with
  `aw1000_leds.main.enabled=0` if the QModem pages time out.
- `aw1000-dashboard` DEPENDS is gated on `@TARGET_qualcommax_ipq807x` because
  the per-device symbol is a profile choice and is not set by
  `CONFIG_TARGET_DEVICE_*` in per-device-rootfs builds. This tree builds the
  AW1000 only.
- `ppe-nss` is rebased: update with
  `cd openwrt && git fetch origin && git reset --hard origin/ppe-nss && ./scripts/feeds update -a && ./scripts/feeds install -a && make defconfig`
  then re-run `prepare.sh`. A plain `git pull` does not update it.
- `luci-app-rustdesk-server` appears twice in `tmp/.packageinfo` (two feed
  copies). It is not selected; leave it unselected.
- Check the rootfs partition before adding more: `cat /proc/mtd`,
  `df -h /overlay` on the device. xray-core is tens of MB uncompressed.
